Q2. What is QGridLayout in Qt?
Answer
QGridLayout arranges widgets in rows and columns.

It is useful for forms, settings panels, and interfaces where multiple controls must remain aligned.

Q4. What is QSpacerItem, and how did it cause your GUI problem?
Answer
QSpacerItem reserves space inside a Qt layout.

It can separate widgets or consume available space.
Example
QSpacerItem *spacer = new QSpacerItem(
    630,
    20,
    QSizePolicy::Minimum,
    QSizePolicy::Minimum
);

Here:
- 630 is the preferred width supplied to the spacer.
- 20 is the preferred height.
- QSizePolicy::Minimum influences how the layout may resize the spacer.
The exact space allocated depends on the layout constraints and available geometry.
Problem in my project
The original code used:
spacerHorizontal1 = new QSpacerItem(
    630,
    20,
    QSizePolicy::Minimum,
    QSizePolicy::Minimum
);

This spacer spanned three columns of the grid.

It influenced the grid's minimum size requirements and distribution of horizontal space.

Combined with the label's size hint and other widgets, this made the layout sensitive to differences between Ubuntu and RHEL.
Solution
I removed the unnecessary large spacers and used controlled layout spacing.
lstBoxGroup1Layout->setHorizontalSpacing(12);
lstBoxGroup1Layout->setVerticalSpacing(12);

Interview point: A spacer does not automatically cause a GUI bug. The problem occurs when its size constraints conflict with the available space or other widget requirements.

Interview follow-up
Q: Is setFixedSize() always recommended?

Answer:

No.

Fixed sizes are useful for tightly controlled interfaces, but excessive fixed sizing can cause clipping on systems with different DPI settings, fonts, or translations.

For responsive interfaces, size policies, minimum sizes, and layouts are generally preferable.

In a legacy application with a fixed window size, carefully chosen fixed dimensions may be appropriate.
Q6. What is QSizePolicy in Qt?
Answer
QSizePolicy tells Qt how a widget should behave when additional space is available or when the layout has limited space.

Common policies include:
Policy	Behavior
Fixed	Widget should not grow or shrink
Minimum	Size hint is the minimum desirable size; widget can grow
Maximum	Widget can shrink but should not grow beyond its size hint
Preferred	Size hint is preferred; widget can grow or shrink
Expanding	Widget can grow and actively requests extra space
MinimumExpanding	Widget requires at least its size hint and wants extra space
Ignored	Size hint is ignored during layout calculations


Example
lblSelectedDirGroup1->setSizePolicy(
    QSizePolicy::Fixed,
    QSizePolicy::Preferred
);

This means:
- Horizontally, the label has a fixed size policy.
- Vertically, Qt can adjust its height according to the layout.
Follow-up
Q: What happens if two widgets use QSizePolicy::Expanding?

Qt distributes available space according to stretch factors, size hints, minimum and maximum sizes, and the widgets' size policies.

Q9. What is Qt's parent-child ownership mechanism?

Part 3: Qt Signals and Slots
Q12. What are signals and slots in Qt?
Answer
Signals and slots are Qt's mechanism for communication between objects.

A signal indicates that an event occurred.

A slot is a function that can respond to the signal.
Example
connect(
    btnBrowseGroup1,
    SIGNAL(clicked()),
    this,
    SLOT(browseGroup1Clicked())
);

Explanation
When the user clicks the Browse button:
User clicks Browse
        |
        v
QPushButton emits clicked()
        |
        v
Qt signal-slot connection
        |
        v
browseGroup1Clicked()
        |
        v
Directory selection functionality

Follow-up
Q: What happens if the signal and slot are not connected?

The button may still receive click events, but the intended slot will not execute through that connection.
Q13. What is the difference between direct and queued connections?
Answer
Qt supports multiple connection types.

Two important types are:

Direct connection

The slot executes immediately in the thread that emits the signal.

Queued connection

The slot invocation is posted to the event queue of the receiver's thread and executes when that thread processes the event.
Example
connect(
    sender,
    SIGNAL(dataReady()),
    receiver,
    SLOT(processData()),
    Qt::QueuedConnection
);

Interview follow-up
Q: Which connection is used by default?

Qt::AutoConnection.

For an automatic connection, Qt uses a direct connection if the receiver lives in the thread currently emitting the signal. Otherwise, it uses a queued connection.

This is particularly important when using worker threads.

Q21. What happens if the total widget width exceeds the parent width?
Answer
Suppose the parent group has 600 pixels of available width.

The child layout requires:

Directory      = 380 pixels
Button         = 68 pixels
Column spacing = 24 pixels
Left margin    = 24 pixels
Right margin   = 24 pixels

Depending on the widget hierarchy and layout constraints, content may become clipped, extend beyond the available region, or force a larger minimum size.

Q22. What is the difference between setColumnMinimumWidth() and setColumnStretch()?
Answer
setColumnMinimumWidth() specifies the minimum width of a grid column.
layout->setColumnMinimumWidth(1, 380);

Column 1 should be at least 380 pixels wide.

setColumnStretch() specifies how additional available space is distributed.
layout->setColumnStretch(1, 1);

Column 1 receives a share of additional space according to its stretch factor.

Example:
layout->setColumnStretch(0, 0);
layout->setColumnStretch(1, 1);
layout->setColumnStretch(2, 0);

This allows the middle column to expand when extra space is available.

Follow-up: Does stretch factor zero guarantee a fixed column width?

No.

A stretch factor of zero does not make the column fixed. Widget size hints, minimum sizes, maximum sizes, and other layout constraints still matter.

Part 5: C++ Memory Management and Linux Questions
Q24. Does Qt automatically prevent every memory leak?
Answer
No.

Qt automatically manages the lifetime of child QObject instances through parent-child ownership.

However, memory leaks can still occur when:
- Dynamically allocated objects have no owner.
- Resources are allocated outside Qt's ownership system.
- Objects are never deleted.
- Custom classes retain unmanaged resources.
- Ownership is unclear.
For example:
QWidget *widget = new QWidget();

If this object has no parent and is never deleted, it may leak.

But:
QWidget *widget = new QWidget(this);

makes this its parent, so the widget is deleted when its parent is destroyed.

Follow-up: Who owns a QLayout?

A layout installed on a widget is normally managed by that widget. Qt also manages child layout items according to its layout ownership rules.

Q26. What is the difference between new, delete, and Qt parent ownership?
Answer
In standard C++:
int *ptr = new int(100);

delete ptr;

The programmer manages the dynamically allocated object's lifetime.

In Qt:
QPushButton *button = new QPushButton("Save", this);

The button is dynamically allocated, but its parent owns it.

When the parent is destroyed, the button is destroyed automatically.

Interview follow-up: What happens if you manually delete a Qt child widget?

Qt removes the deleted object from its parent's child list, so the parent will not delete it again.

However, other raw pointers referring to the deleted object become dangling pointers.

Part 6: Most Important Interview Scenario
Interviewer: You have 4–5 years of C++ Linux experience. Explain your Qt GUI issue from beginning to end.
Recommended 2-minute answer
Answer:

"In my project, I worked on a Linux endpoint security application developed using C++ and Qt.

One of the modules was the Real Time Monitor, which allows users to enable or disable real-time scanning, configure monitored directories, and manage quarantine settings.

The GUI was displaying correctly on Ubuntu 24.04 LTS, but on RHEL 9.6, I encountered a layout issue.

The directory input field and directory list were shifted horizontally, and buttons such as Browse, Add, Exclude, Remove, and ClearAll were partially hidden.

I investigated the Qt widget hierarchy and found that the directory section was implemented using QGridLayout with large QSpacerItem objects.

The layout depended on widget size hints, font metrics, and available space, which could vary between Linux environments.

To address this, I modified the layout by removing unnecessary large spacers and configuring controlled column widths, widget sizes, margins, and spacing.

I also adjusted the parent QVBoxLayout to maintain consistent positioning of the Monitor status and directory configuration groups.

The changes were limited to the GUI layout, so the existing scanning logic, configuration handling, and Qt signal-slot connections were preserved.

The main learning from this issue was that cross-platform Qt applications should not depend on hardcoded spacer values without considering the available layout geometry and platform-specific widget dimensions."

After testing successfully, you can add:

"I rebuilt the application and verified the layout and button functionality on both Ubuntu 24.04 and RHEL 9.6."

One additional question worth preparing: What happens if a real-time antivirus scanner performs a long-running scan directly in the Qt GUI thread?

The answer is that the GUI event loop can become blocked, making the interface unresponsive. A better design is to perform scanning in a worker thread or separate daemon process and communicate results to the GUI through appropriate asynchronous mechanisms.
